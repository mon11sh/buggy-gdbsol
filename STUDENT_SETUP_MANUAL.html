00

The big picture: what you are about to run

GDB is a small bank built as many little programs (“microservices”) that talk to each other, plus a website. Each backend service is a Python program; the website is a React app.

The four dark services (auth, users, accounts, transactions) save data, so they need a database. The four grey ones are pretend “helper” services (Aadhar check, company check, notifications, payment gateway) and need no database. You never change the code to switch databases — you only change one setting. That is the whole point of this project.

1.1  Python 3.11 or newer (runs every backend service)

  1. Open the download page. In your browser go to python.org/downloads.
  2. Download the installer. Click the big yellow “Download Python 3.13.x” button (any 3.11, 3.12 or 3.13 is fine). The .exe lands in your Downloads folder.
  3. Run the installer. Double-click the downloaded file and approve the Windows prompt.
  4. Tick “Add python.exe to PATH”. It is the checkbox at the bottom of the first screen (see FIG 01). This is the step everyone forgets — do it before anything else.
  5. Click “Install Now” and wait for it to finish.
  6. Finish up. If a “Disable path length limit” button appears at the end, click it, then click Close.

Then open a new PowerShell window and check it worked:

PowerShell
PS> python --version
Python 3.11.9          # any 3.11 / 3.12 / 3.13 is fine
PS> pip --version
pip 24.0 from ...
If “python” is not recognized

You forgot the PATH tick. Re-run the installer → “Modify” → tick “Add to PATH” → close and reopen the terminal. A brand-new terminal is required for the change to take effect.

1.2  Node.js + npm (runs the web frontend)

  1. Open nodejs.org.
  2. Download the LTS build. Click the green button that says “LTS” (Long-Term Support = the stable one). It downloads a .msi installer.
  3. Run it. Double-click, click Next, accept the licence, Next.
  4. Keep the defaults for the install folder and the feature list — just keep clicking Next. npm is included automatically.
  5. Tools for Native Modules: leave that checkbox unticked (not needed here) → Next.
  6. Click Install, approve the prompt, then Finish.

Open a new terminal and verify:

PowerShell
PS> node --version
v20.11.1
PS> npm --version
10.2.4

1.3  VS Code (where you type the commands)

  1. Download from code.visualstudio.com — click “Download for Windows”.
  2. Install. Run the installer, accept the agreement, keep clicking Next.
  3. On “Select Additional Tasks” tick “Add to PATH” and both “Open with Code” options → Next → Install → Finish.
  4. Open the project. In VS Code: File → Open Folder → select the gdb-service folder → Select Folder.
  5. Open a terminal inside it. Menu Terminal → New Terminal, or press Ctrl+`. Make sure the dropdown on the right of the terminal says PowerShell.
This is your command line

Every python … command in this manual is typed into that VS Code terminal, with the gdb-service folder open.

1.4  PostgreSQL + pgAdmin  only for the pgAdmin database

One installer gives you both the PostgreSQL server and pgAdmin (the window you look inside it with).

  1. Open the download page postgresql.org/download/windows and click “Download the installer”.
  2. Download the latest version (16 or 17) for Windows x86-64 from the EDB page.
  3. Run the installer, approve the prompt, click Next through the welcome and the default install folder.
  4. Select Components: keep PostgreSQL Server, pgAdmin 4 and Command Line Tools ticked. You can untick Stack Builder. → Next.
  5. Keep the default Data Directory → Next.
  6. Set the superuser password. This is the password for the postgres user. Type it twice and write it down — you pass it to setup_env.py later (see FIG 02). → Next.
  7. Keep Port 5432 → Next, keep the default locale → Next → Next → Install.
  8. Finish. If it offers Stack Builder at the end, untick it and click Finish. The server now runs automatically as a Windows service.

Check it installed by opening pgAdmin from the Start menu (it will ask for that same password), or from a new terminal:

PowerShell
PS> psql --version
psql (PostgreSQL) 16.3
Remember the difference

PostgreSQL = the database engine that must be running (it auto-starts as a service). pgAdmin = a window to look inside it. Our app talks to PostgreSQL; you use pgAdmin only to watch the data appear.

1.5  MySQL + Workbench  only for the MySQL database

  1. Download the MySQL Installer for Windows. The smaller “web-community” installer is fine. (You can skip the “No thanks, just start my download” login.)
  2. Run it and choose Setup Type “Developer Default” (this includes the Server and Workbench together) → Next → Execute to download and install the components. Approve any prompts.
  3. Configure the server: Type = Standalone → Next; keep Development Computer and Port 3306 → Next.
  4. Authentication: choose “Use Strong Password Encryption (RECOMMENDED)” → Next.
  5. Set the ROOT password. Type it and write it down — you pass it to setup_mysql.py later. → Next.
  6. Windows Service: keep the defaults (start MySQL at boot) → Next → Execute → Finish, and complete the remaining screens with defaults.
No database to create

Do not make a database by hand. The app creates gdb for you on first run. Open MySQL Workbench and connect as root to check it works.

1.6  SQLite & In-Memory  nothing to install

SQLite is built into Python already. In-Memory uses your computer’s RAM. Both work out of the box — skip straight to setup. (Optional: to peek at a SQLite file, install the free DB Browser for SQLite.)

1.7  Supabase  free cloud account

Supabase is PostgreSQL hosted on the internet — nothing to install, just an account.

  1. Sign in. Go to supabase.com, click “Start your project”, and sign in (GitHub or email).
  2. New project. Click “New project” and pick (or create) an Organization.
  3. Fill the form. Enter a project Name, set a Database Password (write it down), and choose a Region near you (e.g. Mumbai or Singapore).
  4. Create & wait. Click “Create new project” and wait ~2 minutes while it provisions.
  5. Grab the connection string in step 04: top bar Connect → Session pooler → Copy (see FIG 04). You will paste your password into it there.
02

Prepare the codebase (one time)

This installs a private Python environment for each service and the frontend’s packages. You run it once, no matter which database you later choose.

  1. Open the project folder in a terminal. Everything happens inside gdb-service.
  2. Run the setup script. It creates a venv for each of the 8 services and runs npm install for the frontend.
  3. Wait for it to finish. The first run downloads packages, so it can take a few minutes.
PowerShell — inside gdb-service
PS> cd "C:\...\Trainer_PythonFullstack_GDB\gdb-service"
PS> python Gdb.Setup
▶ auth_service      creating venv ... installing requirements ✅
▶ users_service     creating venv ... installing requirements ✅
▶ accounts_service  ... ✅   ▶ transactions_service ... ✅
▶ frontend          npm install ✅
🎉 All environments ready.
Smart & repeatable

Safe to run again any time. If a venv already exists it only installs what is missing. Force a clean rebuild with python Gdb.Setup --force.

03

Choose which database to use

All five run the exact same app. Pick one to start with — In-Memory or SQLite are the easiest.

In-Memory

EASIEST

Lives in RAM. Nothing to install, nothing saved — resets on restart. Great for a fast demo.

setup_provider.py inmemory

SQLite

EASY

Saves to small .db files in each service. No server needed; data survives restarts.

setup_provider.py sqlite

PostgreSQL

NEEDS SERVER

Real database you can inspect in pgAdmin. Each service gets its own gdb_*_db.

setup_env.py PW postgres

MySQL

NEEDS SERVER

Real database viewable in MySQL Workbench. All services share the gdb database.

setup_mysql.py "mysql://…"

Supabase

CLOUD

PostgreSQL on the internet. No local server; needs a free account and a connection string.

setup_supabase.py "postgresql://…"

04

Set up your chosen database

Run one of the following. Each writes the correct .env settings into the four data services for you. You never edit files by hand.

4.A  In-Memory

no server needed
PS> dotnet run --project tools/Gdb.Setup inmemory
🗃️  GDB → INMEMORY (no server needed)
✅ users · auth · accounts · transactions → inmemory

4.B  SQLite

no server needed
PS> dotnet run --project tools/Gdb.Setup sqlite
🗃️  GDB → SQLITE (no server needed)
✅ Each service creates its own file: gdb_users.db, gdb_accounts.db, …
Where the files appear

After you run the app, look for gdb_accounts.db inside accounts_service/, and similar files in the other three data services.

4.C  PostgreSQL (pgAdmin)

First make sure the PostgreSQL server is running (it starts with Windows by default). Then pass your postgres password — the second word is the username, which is postgres:

local PostgreSQL server must be running
# format:  dotnet run --project tools/Gdb.Setup <password> <username>
PS> dotnet run --project tools/Gdb.Setup MyPgPass123 postgres
✅ users · auth · accounts · transactions → postgres @ localhost:5432

Each data service will auto-create its own database. After you start the app, open pgAdmin and refresh:

4.D  MySQL (Workbench)

Make sure the MySQL server is running, then pass one connection string with your root password (leave the database as gdb — it is created for you):

local MySQL server must be running
# format:  mysql://<user>:<password>@<host>:<port>/<database>
PS> dotnet run --project tools/Gdb.Setup "mysql://root:MyRootPass@localhost:3306/gdb"
✅ users · auth · accounts · transactions → mysql @ localhost:3306/gdb
Quotes matter

Wrap the connection string in double quotes so PowerShell keeps it as one piece. In Workbench you will find all tables inside the single gdb schema.

4.E  Supabase (cloud)

In your Supabase project open Connect (top bar) and copy the Session pooler URI (it ends in :5432/postgres). Paste your database password into it where it says [YOUR-PASSWORD], then:

needs internet
PS> python setup_supabase.py "postgresql://postgres.abcd:MyDbPass@aws-0-ap-south-1.pooler.supabase.com:5432/postgres"
✅ users · auth · accounts · transactions → supabase (SSL)
Use the Session pooler (port 5432)

The Transaction pooler (port 6543) does not work with our driver. If login is slow the first time, that is just the cloud waking up.

Run all the servers

One command starts all 8 backends and the frontend, each in its own titled window.

PowerShell — inside gdb-service
PS> dotnet run --project tools/Gdb.Runner
🚀 GDB — Starting all services
▶️  [auth_service]         http://localhost:8004
▶️  [users_service]        http://localhost:8003
▶️  [accounts_service]     http://localhost:8001
▶️  [transactions_service] http://localhost:8002
▶️  [aadhar/company/notification/payment]  8005–8008
▶️  [frontend] npm run dev  →  http://localhost:3000

Nine windows open. A window that stays open showing an error means that service failed — the title tells you which one, and you can read the message (usually a wrong DB password or a port already in use). Each backend window should end with Application startup complete.

Open http://localhost:3000 (Vite may use :5173 — use whatever it prints) and log in:

Auto-reload while editing

Add --reload (dotnet run --project tools/Gdb.Runner --reload) so services restart when you change code. It uses more memory; skip it for a plain demo.

06

Use it & prove it works

A quick tour that exercises every data service, so you know the database is really wired up.

  1. See the seed accounts. The Accounts page already lists two accounts (1000 & 1001) created automatically on first start.
  2. Create a savings account. Use demo Aadhar 123456789012 → Verify → Continue → PIN 1234 → Create. You should get a new account number.
  3. Transfer money. Move funds between two accounts. A success here proves the transactions service and its database are healthy.
  4. (Real DBs) look inside. In pgAdmin / Workbench / Supabase, run SELECT * FROM accounts; and watch your new row appear.
Swagger API docs

Every backend has interactive docs at http://localhost:<port>/api/v1/docs — e.g. accounts at :8001/api/v1/docs. Handy for showing the API directly.

07

Switching from one database to another

The golden rule: stop everything first, then re-point, then start again.

  1. Close all the windows (or free the ports) so nothing is holding 8001–8008.
  2. Run the setup command for the new database (section 04).
  3. Start again with dotnet run --project tools/Gdb.Runner.
stop → switch → start
# 1) stop everything (frees the ports)
PS> taskkill /F /IM python.exe 2>$null ; taskkill /F /IM node.exe 2>$null
# 2) pick a new database, e.g. SQLite
PS> dotnet run --project tools/Gdb.Setup sqlite
# 3) start again
PS> dotnet run --project tools/Gdb.Runner
Data does not follow you

Each database is its own separate store. Accounts made on MySQL will not appear on SQLite — every provider starts fresh with the two seed accounts. That is expected, not a bug.
